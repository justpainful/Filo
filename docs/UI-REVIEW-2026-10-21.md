# Filo 0.1.1 — UI review, 21 October 2026

## Result

The reported dark-on-grey metadata window is reproduced and corrected in the shared native rendering layer. The revision is built and packaged as `dist/Filo-Setup-0.1.1.exe`. The executable in `build/stage` has the same SHA-256 as the final Release build (see `out/ui-review/release-manifest.json`). The installer has been compiled, not installed/uninstalled during this review.

## What changed

- Light glass keeps the reference's saturated backdrop colour (+0.20 lift, 2.5% veil), but has a weighted sRGB brightness floor of 0.72. Dark glass has a bounded dark tint. Text polarity follows the selected theme. Desktop icons are diffused at sigma 28 dip before drawing.
- Opaque neutral secondary/tertiary text stays legible over the material. The contrast regression samples 5,832 surfaces and checks three text levels at >=4.5:1. This covers the material/palette pair, not every widget overlay or disabled state.
- The wheel now defaults to the measured 265 dip radius, with a work-area cap. Sector geometry/hit testing is retained; frosting, blue hover, centre-pill readability and narrow quiet edge highlights are improved.
- Metadata has a 620x720 dip preferred body, a file header, separated tabs/search, rounded field surface, 38 dip field rows, alternating quiet fills and full-value tooltips. The selected segment and keyboard focus are visible.
- Primary tool actions, including audio Apply, are blue. Edit Photo's Reset is readable over its dark preview, and the preferred 900 dip editor height/391 dip preview better follows the official reference while small screens retain scrolling.
- Continuous animation uses low-priority timer frames. The former posted-frame loop could starve native typing/clicks once a text field blinked its caret. Dialog deletion during render/message dispatch is deferred. Standard clipboard messages and WM_UNICHAR reach the custom input controls.

## Limits and remaining work

The glass is a blurred desktop snapshot, captured before the window appears and refreshed after moving/resizing. Underlying motion does not update continuously. Full Windows system-colour high contrast and Arabic translations remain incomplete. The RTL debug gallery has crowded controls near its bottom; the gallery is not a daily processing window. The official Join Videos and metadata reference screenshots are unavailable in the workspace, so their layout is assessed for usability, not verified as a pixel match. Explorer drag/drop, installer install/uninstall and the complete processing matrix were not requalified by this UI revision.

The headless `--tool-run edit-metadata` harness raced the initial asynchronous load and returned failure for its preset. The visible UI save was therefore tested directly and passed; the headless race is recorded in KNOWN-LIMITATIONS.md. This UI revision does not close the full master directive's production acceptance checklist.
